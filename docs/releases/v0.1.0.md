# Tarkka v0.1.0

Tarkka v0.1.0 is the first public release of the local, evidence-grounded research
infrastructure. It provides a deterministic, LLM-optional path from a preserved source through
normalized research records, evidence-backed claims, proof bundles, offline verification, and
replay.

## Highlights

- Ingest local text and Markdown sources into immutable, content-addressed Artifacts and normalized
  Documents.
- Extract deterministic sentence-level Claims with exact passage Evidence, then inspect their
  provenance with `tarkka why` and claim receipts.
- Create schema-v3 `.tarkka` proof bundles; verify their integrity offline; and replay supported
  deterministic parsers against the frozen normalized Document.
- Use replaceable scholarly discovery adapters for OpenAlex, Crossref, Semantic Scholar, and arXiv.
- Inspect native bibliography, citation, and resource-link observations without replacing source
  structure with inferred data.
- Use staged CLI and MCP interfaces for capability discovery, document expansion, claim lineage,
  context-bounded retrieval, comparison, and replay.

## Installation

Download the wheel attached to this GitHub Release, then install it locally:

```bash
python -m pip install ./tarkka-0.1.0-py3-none-any.whl
```

Tarkka is not published on PyPI in this release. Optional features remain opt-in extras; see the
README for PostgreSQL, MCP, Docling, and embedding setup.

## Compatibility and migration

This is the first public release, so no migration from an earlier public version is required.
Tarkka preserves the compatibility contracts documented for proof bundles and adapter conformance.
The canonical lexical capability is `research.search`; `research.retrieval.search` and MCP
`retrieval_search` remain compatibility aliases.

## Known limits

- The default local profile uses JSON metadata storage and local content-addressed Artifact storage.
- Model-assisted extraction, rich-document parsing, PostgreSQL, and MCP are optional integrations.
- Retrieval embeddings remain opt-in and are not enabled by default.
- Proof-bundle replay is deterministic only for the explicitly supported parser identities recorded
  in each bundle.

## Validation

This release candidate was validated with the deterministic test suite, strict type checking,
linting, SQL migration linting, a source and wheel build, a clean wheel installation, and the
offline proof/replay walkthrough. The tag-driven release workflow rebuilds the source distribution
and wheel from the release tag, verifies a clean installation, generates SHA-256 checksums, and
attaches those artifacts to this GitHub Release.
